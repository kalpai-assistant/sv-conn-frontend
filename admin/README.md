# EazyServ Admin

The standalone admin console (epic SVC-407; scaffold SVC-421, sign-in SVC-422). It is its own app with its own `package.json` and lockfile. It shares nothing at build time with the consumer app in the repo root.

## Run

```bash
cd admin
npm ci
npm run dev      # http://localhost:5174 (strictPort; it fails rather than move to another port)
```

Other scripts: `npm run build` (→ `dist/`), `npm run lint`, `npm test`, `npx tsc --noEmit`, `npm run test:e2e` (Playwright, API mocked; run `npx playwright install chromium` once first).

The API base comes from `VITE_API_BASE_URL` (see `.env.example`). It defaults to `/api/v1`, like the consumer app.

## Stack

It mirrors the consumer app: Vite, React 19, TypeScript, Tailwind 4, shadcn/ui (new-york, `components.json`), TanStack Router with file-based routes, lucide icons and Vitest.

- `src/routeTree.gen.ts` is generated by the router plugin on `dev`/`build`. Never edit it, but do commit it, because typecheck reads it.
- The design tokens in `src/styles.css` are copied from `../src/styles.css`. Keep the two in step.
- `src/lib/api.ts` starts from the consumer `apiFetch`, but its session handling is the admin model below.

## Sign-in (SVC-422)

Email + password at `/login`, then a TOTP code at `/totp`, or `/totp-setup` on a first login. There is no other way in.

- The session token lives in `sessionStorage` and goes out as a Bearer header. A response carrying `X-Admin-Token` replaces it.
- The challenge token between the two steps lives in memory only, so reloading a code screen goes back to `/login`.
- A 401 from a session-gated call signs out. A 401 from `/login` or `/totp/*` is a form error.
- The guard is the `beforeLoad` in `src/routes/_authed.tsx`. It reuses `GET /admin/auth/me` for 5 minutes, so a role change can take that long to reach the sidebar. The backend still checks the role on every request.
- Which role sees what is the `roles` field in `src/lib/nav.ts`. A route the role's sidebar doesn't list redirects to `/`, so a new screen needs a nav entry before anyone can open it.

## Native-binary pins

`optionalDependencies` pins the Linux and macOS builds of rollup, lightningcss and the Tailwind oxide engine. This guarantees that a lockfile written on Windows still installs on CI's Linux runner and on Macs (the root app has the same gap). When you upgrade vite or tailwind, bump these pins to the versions that the new lockfile resolves.
