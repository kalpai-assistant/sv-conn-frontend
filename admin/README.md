# EazyServ Admin

The standalone admin console (epic SVC-407; this scaffold is SVC-421). It is its own app with its own `package.json` and lockfile. It shares nothing at build time with the consumer app in the repo root.

## Run

```bash
cd admin
npm ci
npm run dev      # http://localhost:5174 (strictPort; it fails rather than move to another port)
```

Other scripts: `npm run build` (→ `dist/`), `npm run lint`, `npm test`, `npx tsc --noEmit`.

The API base comes from `VITE_API_BASE_URL` (see `.env.example`). It defaults to `/api/v1`, like the consumer app.

## Stack

It mirrors the consumer app: Vite, React 19, TypeScript, Tailwind 4, shadcn/ui (new-york, `components.json`), TanStack Router with file-based routes, lucide icons and Vitest.

- `src/routeTree.gen.ts` is generated by the router plugin on `dev`/`build`. Never edit it, but do commit it, because typecheck reads it.
- The design tokens in `src/styles.css` are copied from `../src/styles.css`. Keep the two in step.
- `src/lib/api.ts` is a copy of the consumer `apiFetch`, without the auth logic.

## What's placeholder

Everything except the shell:

- `/login`: there is no form yet. Auth is SVC-407 A2.
- The `_authed` layout has no guard. A2 adds a `beforeLoad` there.
- All 9 sidebar screens (Operator, Analytics and Support) are placeholder pages.
- Deploy: `.github/workflows/deploy-admin.yml` is a stub that fails on purpose. admin.eazyserv.com does not exist yet.

## Native-binary pins

`optionalDependencies` pins the Linux and macOS builds of rollup, lightningcss and the Tailwind oxide engine. This guarantees that a lockfile written on Windows still installs on CI's Linux runner and on Macs (the root app has the same gap). When you upgrade vite or tailwind, bump these pins to the versions that the new lockfile resolves.
